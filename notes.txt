So "I/O bottleneck" basically means:

The CPU is sitting idle because it is waiting for something outside the CPU (network, disk, database, etc.) to finish.

The network waiting time is the big issue for latency.
The number of I/O events per second is the issue for throughput.

Those are related but different bottlenecks.

So the same word "I/O bottleneck" can mean:

slow I/O completion (waiting for network/disk)
too many I/O operations to process (event/syscall overhead)

The Redis section is mostly the second one.
